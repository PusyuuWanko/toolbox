ipcam-companion について

ipCameraViewer(マルチIPカメラビューア)の「動体検知」機能を、CORS非対応の カメラでも使えるようにするための、ユーザー自身の端末上で動く 軽量なローカル中継アプリです。

これは何のためのアプリですか

動体検知は、カメラの映像をブラウザの<canvas>に描画し、 そのピクセルを読み取って前フレームとの差分を計算しています。ところがカメラ側が Access-Control-Allow-Originヘッダーを返さない(=CORS非対応)場合、 ブラウザは安全のためこのピクセル読み取りをSecurityErrorでブロックします。 これはブラウザの正当なセキュリティ機能であり、ipCameraViewer側のバグではありません。

ipcam-companionは、あなたの端末上のhttp://127.0.0.1だけで待ち受ける 小さなHTTPサーバーです。カメラ映像を一度あなたの端末が取得し、ブラウザへは 正当なCORSヘッダーを付けて渡し直します。https://のページから http://127.0.0.1への通信はブラウザのMixed Content制限の対象外 (ループバック特例)なので、これだけで動体検知が正しく動くようになります。

このアプリはあなたの端末上でだけ動くので、「ブラウザから見えるローカルネットワークの カメラを見る」というipCameraViewer本来の設計を一切変えません。Webサーバー側が あなたの家のカメラに通信するわけではありません。

インストールと実行方法

Windows / macOS / Linux

  1. ご自身のOSに合ったファイルをダウンロードしてください。
OSファイル
Windows (64bit)ipcam-companion-windows-amd64.exe
Mac (Apple Silicon)ipcam-companion-darwin-arm64
Mac (Intel)ipcam-companion-darwin-amd64
Linux (64bit)ipcam-companion-linux-amd64
  1. ダウンロードしたファイルを実行してください。
    • Windows: 「WindowsによってPCが保護されました」という警告 (SmartScreen)が出た場合は「詳細情報」→「実行」を選んでください。これは 署名付き証明書を取得していない個人配布の実行ファイルすべてに出る一般的な 警告です。
    • macOS: 「開発元が未確認のため開けません」と出た場合は、 Finderでファイルを右クリック→「開く」を選ぶと実行を許可できます(初回のみ)。
    • Linux: ターミナルで chmod +x ipcam-companion-linux-amd64 を実行してから ./ipcam-companion-linux-amd64 で起動してください。
  2. コンソール(黒い画面)が開き、「listening on http://127.0.0.1:...」と表示されれば 起動成功です。このウィンドウは動体検知を使っている間、閉じずにそのまま にしてください。ipCameraViewerのページを再読み込みすると自動的に検知して 連携します。
  3. 終了するには、そのウィンドウで Ctrl+C を押すか、ウィンドウを 閉じてください。

自動起動させたい場合は、OSのスタートアップ機能(Windowsのスタートアップフォルダ、 macOSのログイン項目、Linuxの systemd --user 等)にご自身で登録して ください。このアプリ自体には自動起動の設定機能はありません。

Android (Termux経由)

AndroidにはWindows/Mac/Linuxのような「実行ファイルをそのまま起動する」仕組みが 無いため、Termux (F-Droid配布の正規のターミナル・Linux環境アプリ)を経由して実行します。

Google Playstoreの旧Termuxは更新が止まっており不具合が出やすいため、 F-Droid版のTermuxを強く推奨します。
  1. F-DroidからTermuxをインストールします。
  2. ipcam-companion-linux-arm64 をダウンロードし、Termuxの ~/downloads 等の分かりやすい場所に置きます (Termuxからストレージにアクセスするには初回に termux-setup-storage の実行が必要な場合があります)。
  3. Termuxで以下を実行します。 
    chmod +x ipcam-companion-linux-arm64
./ipcam-companion-linux-arm64
  4. Androidはバックグラウンドのプロセスを積極的に停止させるため、動体検知を 使っている間はTermuxアプリ・セッションを前面またはバックグラウンド保持 (通知欄にTermuxのセッション通知が出ている状態)にしておいてください。 termux-wake-lock コマンドを併用すると安定します。

安全性について

このアプリは起動中、ローカルのHTTPサーバーとして動作します。一般に、この種の ローカルサーバーは「起動中は他のどんなWebページからも127.0.0.1のポートに リクエストを送られうる」というリスクを持ちますが、ipcam-companionは以下の対策で これに対処しています。

  • アクセス元の厳格な制限: https://toolbox.pusyuuwanko.com からのリクエスト以外は、Originが一致しない限りすべて拒否します (*のようなワイルドカードでの許可は一切行いません)。
  • 中継先をプライベートネットワークのみに限定: /relayは、宛先がループバック・プライベートIP(192.168.x.x等)・ リンクローカルアドレスのいずれかである場合のみ中継します(DNS応答の すり替えにも、接続の瞬間に毎回検証し直すことで対応しています)。 さらに -allow-hosts 起動オプションで、特定のホスト名/IPだけに 厳密に絞ることもできます(既定では無効=プライベートIPなら何でも許可)。
  • レート制限・同時接続数制限: /relayへの リクエスト頻度と同時接続数に上限を設け、たとえアクセス元チェックを 通過した相手であっても、LAN内を高速に走査する用途には使いにくくしています。
  • X-Content-Type-Options: nosniffを付与し、 カメラ側が想定外のレスポンスを返した場合のMIMEスニッフィングによる 実行リスクを抑えています。
この対策が防げるのは「他のWebサイトが、あなたが開いているページのふりを して勝手にこの中継アプリを使おうとするケース」までです。 あなたの端末上で既に動いているマルウェア(悪意あるプロセス)は、Originヘッダーを 含めて任意の内容を偽装できるため、この種のローカルサーバー固有の対策では 防ぎきれません。これはipcam-companionに限らず、ローカルで待ち受ける あらゆるアプリに共通する一般的な限界であり、端末自体のセキュリティ対策 (信頼できないソフトウェアを実行しない等)で対処すべき領域です。

Origin一致さえすれば理論上はあなたのLAN内へ任意のプライベートIP宛の リクエストを送れますが、これは<img src="http://192.168.x.x/..."> のような素のHTMLタグでこのアプリが無くても今日から可能な範囲を 実質的に超えるものではなく、このアプリの導入によって新たに生まれる攻撃面では ありません。

また169.254.0.0/16(リンクローカル、クラウド環境のメタデータ エンドポイントを含む)も中継対象として許可していますが、これは本アプリが 「個人のデスクトップ/モバイル端末上で動く」ことを前提としており、 クラウドVM上での実行を想定していないためです。

カメラがCookieベースのセッションログインを要求する場合、ipCameraViewer側の JSON設定でカメラごとに cookie フィールドとしてCookie文字列を 指定すると、companionが以後のリクエストにそのCookieを付与し続けます (companion内部のメモリ上にのみ保持し、ディスクへの保存やブラウザへの 送信は行いません。companionを終了すると破棄されます)。

ソースコードは src/ ディレクトリに同梱しています(Go言語)。 ダウンロードした実行ファイルを信用する前に、ご自身でコードを確認したり、 go buildで再ビルドしたものと比較していただいて構いません。

対応OS・ポート

Windows / macOS / Linux(デスクトップ)、およびAndroid(Termux経由)に対応しています。 iOSは対応していません(サードパーティアプリが任意のローカルサーバーを常駐実行する 仕組みが存在しないため)。58712・58713・58714 のいずれかの空いているポートで自動的に待ち受けます。
